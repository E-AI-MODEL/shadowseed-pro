## What reviewers are assessing

The question is **not** whether our author-designed hidden answer looks correct. It is whether the measurement actually distinguishes:

- a model generating more answers or discovering a known missing graph edge;
- an *already available* test or operator merely being revealed through extra context;
- a candidate **enabling a meaningfully different later investigation** in a way that can be isolated from ordinary strong-model search, prompt length, or directly revealed external evidence.

A reviewer must be permitted to conclude **both F1 and F2 are merely conventional diagnosis/planning tasks**, even when both formal validators would accept their positive examples. Rejecting a case is progress; lowering the claim threshold to rescue it is not.

## Reviewer roles and access sequence

**R1 (technical reviewer):** Check each formal before/after system and its negative examples *without observing any model output*. Confirm counterfactual observational equivalence/operational safety, possible failure modes, and whether the proposed "hidden" answer is absent from T0 text. Inspect equations and assessor key.

**R2 (independent conceptual/measurement reviewer):** With no author coaching, decide whether F1 and F2 actually sample **two fundamentally different possibility-making mechanisms**, or only response completeness, troubleshooting or planning with new external facts. Identify an alternative interpretation of observed model success and how a control would disprove it.

**Joint/independent:** Both reviewers independently record a decision per family before discussing disagreements; neither reviewer may be the model generating candidates. Ideally a third reviewer adjudicates conflicting **reasoned** decisions. Do not automatically convert a disagreement to "pass."

**Public-key disclosure:** the example solutions are committed to GitHub. Review may test the logic, but cannot make this set sealed confirmatory evidence. A separate held-out set, protected from model/retrieval exposure and curated after preregistration, is required before confirming any efficacy claim.

## Blocking criteria (all must be answered per family)

| ID | Mandatory question | Pass standard | Fail/UNKNOWN action |
|---|---|---|---|
| **C0 — Distinct construct** | What actual kind of *future possibility* changes? | Case identifies a meaningful later question, comparison, admissible action or experiment, distinct from simply another generated sentence | **Stop** if only "more ideas" or a missing fixed edge |
| **C1 — Before-state proof** | Is the original barrier demonstrable? | F1 two worlds observationally indistinguishable with T0 archive; F2 no safe path under documented microstep actions | **Stop** if initial goal was already directly accessible under the same conditions |
| **C2 — Non-tautological after-state** | Does an independently admissible intervention make a *specific* downstream difference? | Consequence not true simply because author added a permissive rule; no invented tool/device accepted without witness | **Stop** if setting a rule or naming a new operator makes success automatic |
| **C3 — Negative cases** | Do plausible wrong candidates fail? | Same-longer archive, nonindependent meter, uninformative sample (F1); serial/coarse/sham operation, missing certificate (F2) are rejected | **Stop** if ordinary bad suggestions pass the evaluator |
| **C4 — Separation from author answer** | Did the task give away the enabling idea? | T0 envelope contains no future witness, target hypothesis/operation label or exact correct follow-up; visible instructions and cues documented | **Revise** if key or title leaked into model prompt |
| **C5 — Independent meaningfulness** | Is an apparent opening meaningful, not trivial output variation? | Independent conceptual reviewer can describe what new inquiry/action is possible and why an ordinary search baseline might fail or match it | **Stop** if only routine instrument choice/new tool permission, or if reviewer cannot distinguish |
| **C6 — Strong fair comparator** | Could a frontier model with ordinary notes and equal resources solve it? | Protocol includes a strong **non-SSL** baseline; its correct success is counted fully, no straw-man prompt/budget | **Stop** if success is defined by beating a deliberately weak baseline |
| **C7 — Candidate causality** | Can candidate and new evidence be separated? | Precommitted T0 candidate; independent T1 revealed uniformly; distinct candidate-removed, irrelevant-note, and evidence-removed checks | **Stop** if more context alone is scored as candidate effect |
| **C8 — Information provenance** | Who actually introduced the new possibility? | Author-defined case rules, device witness, model proposal, external source and human test decisions credited separately | **Stop** if an externally provided affordance is described as invented by model |
| **C9 — Scope and evidence** | Are overclaims blocked? | No claim about internal latent absence, novel scientific fact, changed model weights or confirmed SSL advantage from the G0 cases | **Stop** if validation of toy equations is described as thesis validation |
| **C10 — Held-out integrity** | Can future model tests avoid answer contamination? | Public illustrative key retained as provenance; *new* post-preregistration sealed cases and no tool/retrieval exposure are required for confirmatory run | **Stop** if GitHub examples are called confidential holdouts |
| **C11 — Second-order dependence** | Does the first opportunity enable a **distinct later question/test**, not just one answer or first action? | T3 investigation has a new discriminating criterion; its dependence on candidate, T1 witness and T2 step can be tested separately, with strong matched ordinary models | **Stop** if the entire effect is only immediate diagnosis, a repeated toggle, or a chain of opportunities stipulated by the author |

**Mandatory fail rule:** If **any** C0–C11 is fail or unknown in either family, **G0 is NOT PASSED**. Report all fail and unknown entries; do not compute an average that hides them. A reviewer may explicitly reject both case families.

## Acceptance and rejection

**Accept G0 for *feasibility study design only*** when: both distinct families satisfy every C0–C11 with two independent reasoned approvals, disagreement is resolved transparently, no fatal answer leakage exists, and a new sequestered confirmatory dataset and pre-registration path are specified. G0 acceptance **does not** prove Q1, Q2, efficacy, or the usefulness of weightless memory; it authorizes designing a bounded model experiment.

**Reject G0** if either family collapses into generic troubleshooting, missing edge completion, simple device-permission revelation, a trivial axiom relaxation, or a direct restatement of the withheld answer. Replace the failing case with a genuinely different, predeclared construct rather than expanding arbitrary evaluator permissiveness.

## Additional stage after G0 — no shortcut

- **Q1:** strong-model ordinary-generation selection distribution, matched alternate search, semantic relation-family judging; absence in samples ≠ model-internal impossibility.
- **Q2:** independently validated new downstream investigability (including a second-generation T3 test where meaningful) after candidate, with exact candidate + transformation ablations. An author-prescribed chain is not itself evidence of possibility-making.
- **Coupling:** an *actual*, longitudinal, weightless-shadow process against matched ordinary-model deliberation, ordinary persistent notes and shuffled-candidate control.
- **External validity:** new data, humans and tools credited to their actual role, with held-out tasks and replicated model tiers.

A "shadow-like" prompt alone or a green formal oracle is not the Shadowseed system. Any later paid model run must be **explicitly opt-in**, budget-capped, and reported including failures. The archived 24-call v0 pilot stays historical.
