# Shadowseed 0.11 Implementation Matrix

Status: Working draft  
Date: 2026-10-02  
Depends on: ADR-009 and Prompt Contract PvA  
Target: 0.11.0 Research Preview

## Purpose

This matrix translates ADR-009 into an implementation order. It is intentionally broader than a file checklist: the component model comes first, then cross-component alignment, then concrete code/UI/test work.

The document has three layers:

- **A. Component matrix**: what each component owns, receives, emits and may mutate.
- **B. Alignment / impact matrix**: which components affect one another and where semantic drift can occur.
- **C. Implementation matrix**: exact change areas, files, tests, dependencies and proposed PR order.

The matrix is the working bridge between architecture, prompts, runtime, Workbench UX and release planning.

# A. Component matrix

## A1. Answer generation

**Purpose**  
Produce the ordinary first-pass answer to the current user question.

**Primary input**  
Visible conversation history + current user question.

**Output**  
Draft answer.

**Decision owner**  
Generation role.

**May mutate**  
Draft text only.

**Must not mutate**  
Seed authority, recurrence, Gate state, evidence or promotion.

**Human / SSL orchestration**  
SSL acts automatically. No human handoff belongs here.

**Current source anchors**  
- src/shadowseed/chat.py
- src/shadowseed/surfacing.py
- src/shadowseed/adapters/models.py

**Current alignment issue**  
The shared host prompt contains strong style instructions and its output is also the material seen by the detector. Host-prompt style can therefore indirectly alter the seed population.

**0.11 contract**  
Generation stays authority-neutral. Generation, detection and revision are separate roles even when one physical model implements all three.

## A2. Detection context

**Purpose**  
Define exactly what the detector is allowed to inspect.

**Chat input**  
Current pair = current question + current draft answer.

**Source input**  
Current source observation = source chunk + source provenance.

**Output**  
Typed detector input package.

**Decision owner**  
Detection-context builder.

**May mutate**  
Context/provenance metadata only.

**Must not mutate**  
Seed state or authority.

**Human / SSL orchestration**  
Automatic.

**Current source anchors**  
- src/shadowseed/chat.py
- src/shadowseed/detection/model_detector.py
- source-ingest application path

**Current alignment issue**  
Live chat currently calls detector.detect_seeds({"text": final_answer}), so the user question is absent from detector input.

**0.11 contract**  
Chat detection receives explicit question + draft. Source ingestion remains a separate observation contract. Pair is never reused as recurrence representation.

---

## A3. Detector

**Purpose**  
Propose zero or more candidate directions that could deepen the specific answer/question context.

**Input**  
Detection context.

**Output**  
Raw candidate observations + parser diagnostics.

**Decision owner**  
Detection role.

**May mutate**  
Nothing in authority state. It may emit observations.

**Must not decide**  
Truth, evidence, recurrence, promotion or relevance.

**Human / SSL orchestration**  
Automatic. Human inspection is optional.

**Current source anchors**  
- src/shadowseed/detection/model_detector.py
- src/shadowseed/prompts.py

**Current alignment issues**  
- live generative prompt sees answer-only;
- English few-shots may prime language/form;
- no explicit NONE contract;
- max_seed_words is not supplied to the detector prompt;
- prompt provenance is currently coarse.

**0.11 contract**  
Versioned prompt asset, explicit current-pair input, zero-candidate result allowed, language tied to current question, exact prompt id/version/hash logged.

---

## A4. Observation ledger

**Purpose**  
Preserve what the detector observed and under which causal conditions.

**Input**  
Raw detector candidates + context/provenance + SSL exposure state.

**Output**  
Immutable CandidateObservation records and optional links.

**Decision owner**  
Observation provenance layer.

**May mutate**  
Append-only observation records.

**Must not mutate**  
Occurrence, trace, evidence, Gate authority or promotion.

**Human / SSL orchestration**  
Automatic.

**Current source anchors**  
- src/shadowseed/observations.py
- src/shadowseed/chat.py

**Current alignment issue**  
Observation schema v2 can mark SSL-exposed output recurrence_eligible when allow_ssl_recurrence/self-reinforcement is enabled. ADR-009 now requires SSL-exposed output to retain a distinct causal identity and, if experimentally authority-bearing, to use a separate SELF_DERIVED Gate signal rather than masquerading as independent recurrence.

**0.11 contract**  
Clean recurrence and self-derived observations are distinct signal classes. Provenance is immutable.

## A5. Intake / atomicity / deduplication

**Purpose**  
Normalize a detector candidate, check atomicity and deduplicate it against existing seed identity.

**Input**  
Candidate text + origin/provenance.

**Output**  
Accepted/rejected candidate and seed identity.

**Decision owner**  
Intake.

**May mutate**  
Weightless seed creation, exact/semantic dedup mechanics, non-authority occurrence/trace support state as currently defined.

**Must not decide**  
Truth or authority.

**Human / SSL orchestration**  
Automatic; optional research inspection.

**Current source anchors**  
- src/shadowseed/intake.py
- src/shadowseed/core_config.py
- src/shadowseed/manager.py

**Current alignment issues**  
- max_seed_words is a downstream hard heuristic but not aligned with detector prompt;
- rejection diagnostics exist but are not consistently surfaced in normal audit;
- semantic atomicity and word-count calibration are mixed in one acceptance boundary.

**0.11 contract**  
Semantic atomicity remains the invariant. max_seed_words is explicit calibration and is available to detector, audit and God mode under Detection/Intake.

## A6. Semantic representation

**Purpose**  
Represent atomic seed meaning for similarity operations.

**Input**  
Atomic seed text.

**Output**  
Normalized embedding.

**Decision owner**  
Embedding layer.

**May mutate**  
Embedding state.

**Must not decide**  
Authority.

**Human / SSL orchestration**  
Automatic unless researcher changes structural config.

**Current source anchors**  
- src/shadowseed/intake.py
- embedding adapters
- src/shadowseed/chat.py

**Downstream impact**  
Deduplication, cluster membership, recurrence, reactivation, relevance/surfacing, probes, retrieval and SSOT search.

**Current alignment issue**

**0.11 contract**

## A7. Recurrence

**Purpose**  
Determine whether the same underlying candidate was independently observed again.

**Input**  
Seed representation + observation identity + existing recurrence state.

**Output**  
Occurrence/cluster recurrence state and typed RECURRENCE signal when eligible.

**Decision owner**  
Recurrence engine.

**May mutate**  
Occurrence/cluster state.

**Must not decide**  
External evidence or authority.

**Human / SSL orchestration**  
Automatic.

**Current source anchors**  
- src/shadowseed/recurrence_clustering.py
- pairwise recurrence logic in src/shadowseed/chat.py
- src/shadowseed/gate/signals.py

**Current alignment issues**  
- cluster/pairwise state is structural but currently looks hot-swappable;
- restored cluster_state can conflict with active recurrence_mode/cluster_threshold;
- SSL-exposed observations must not be recast as clean recurrence.

**0.11 contract**  
Pairwise/cluster operates on seed representations. One physical observation source earns at most one recurrence credit. Structural mode changes require rebuild/new epoch/new session.

---

## A8. Lifecycle

**Purpose**  
Track trace decay, dormancy, reactivation and expiry.

**Input**  
Seed state + passage of turns + reactivation input.

**Output**  
Lifecycle state and, where necessary, an expiry request.

**Decision owner**  
Lifecycle engine.

**May mutate**  
Trace, turns_dormant and non-authority lifecycle metadata.

**Must not independently mutate**  
Positive authority. Where expiry clears authority, ADR-009 requires the authority reset to remain within the canonical authority boundary.

**Human / SSL orchestration**  
Automatic.

**Current source anchors**  
- src/shadowseed/lifecycle.py
- src/shadowseed/models.py

**Current alignment issue**  
Current lifecycle code directly calls manager._set_authority(... status=EXPIRED, weight=0.0) on TTL/vector expiry. That conflicts with ADR-009 governance rule that lifecycle should not independently clear authority when the change is authority-bearing.

**0.11 contract**  
Decide whether expiry is a mechanically allowlisted authority transition or a typed Gate transition, then make doctrine and implementation identical. No hidden second authority writer.

## A9. Validation Gate

**Purpose**  
Be the single authority transition boundary.

**Input**  
Typed ValidationSignal list + current AuthoritySnapshot + named Gate policy.

**Output**  
GateEvent and authority transition.

**Decision owner**  
Validation Gate policy + runtime adapter.

**May mutate**  
Weight, evidence count, promoted eligibility, contradiction authority state and authority version.

**Must not decide**  
Answer wording or relevance.

**Human / SSL orchestration**  
Depends on authority regime and effective Gate policy.

**Current source anchors**  
- src/shadowseed/gate/policies.py
- src/shadowseed/gate/runtime_adapter.py
- src/shadowseed/gate/signals.py
- src/shadowseed/manager.py

**Current alignment issue**  
Canonical evidence_backed and current-Gate revalidation do not mean the same thing.

**0.11 contract**  
One named policy has one semantic meaning. Compatibility policies remain explicitly compatibility-only.

## A10. Human authority actions

**Purpose**  
Allow a human or authorized actor to submit trusted support, contradiction or contradiction resolution.

**Input**  
Actor authorization + seed + source/basis.

**Output**  
Typed Gate input and persisted audit record.

**Decision owner**  
Application authorization boundary plus Validation Gate.

**May mutate**  
Only through canonical application/Gate commands.

**Must not mutate directly**  
Seed weight, status or promotion.

**Human / SSL orchestration**  
This is the main human handoff surface.

**Current source anchors**  
- src/shadowseed/application/auth.py
- evidence submission in application services
- src/shadowseed/application/contradiction_resolution.py
- src/shadowseed/workbench/production_controller.py

**Current alignment issue**  
The backend supports distinct contradiction resolution, but vNext exposes only contradiction submission and verified support.

**0.11 contract**  
Every required human handoff has a visible authorized action and explains what happens if no action is taken.

## A11. Human-SSL orchestration

**Purpose**

**Input**

**Output**  
Session- and seed-level orchestration state:

- menselijke review is optioneel
- jij bent aan zet
- geblokkeerd

**Decision owner**  
Application layer.

**May mutate**  
Nothing. Derived state only.

**Must not decide**  
Authority or evidence.

**Human / SSL orchestration**  
This component *describes* orchestration and is the contract consumed by UX.

**Current source anchors**  
- src/shadowseed/application/inspection.py
- authority_review_seed_ids
- authority profiles

**Current alignment issue**  
The application exposes review IDs but does not expose a general orchestration object; vNext does not consume review-required state.

**0.11 contract**  
One reusable orchestration derivation powers Chat, Shadow, Sources and Audit.

## A18. Configuration / God mode / audit

**Purpose**  
Expose real runtime control without hiding component ownership or rewriting history.

**Input**  
Researcher configuration.

**Output**  
Persisted config + component-specific runtime behavior + audit epoch/digest.

**Decision owner**  
Session/application configuration layer.

**Current source anchors**  
- src/shadowseed/application/models.py
- src/shadowseed/application/sessions.py
- src/shadowseed/workbench/controller.py
- src/shadowseed/storage/integrity.py

- 100% strictness selects legacy_evidence_required;

- stateful changes can be persisted without rebuild semantics.

**0.11 contract**  
Settings are grouped by owning component and tagged immediate/stateful/rebuild-required. A broader behavior/config epoch is persisted per turn.

# B. Alignment and impact matrix

| Upstream component | Downstream component | Required alignment | Failure mode if misaligned |
| --- | --- | --- | --- |
| Generation | Detection | detector knows the actual question answered | interesting but irrelevant seeds |
| Detection context | Detector | chat pair vs source observation is explicit | wrong prompt semantics |
| Detector | Intake | prompt atomicity matches intake heuristics | high rejection / hidden detector failure |
| Detector | Observation ledger | prompt id and causal exposure recorded | unreproducible candidates |
| Observation ledger | Recurrence | only clean independent observations earn RECURRENCE | self-amplification mislabeled as recurrence |
| Observation ledger | Gate | self-derived signal remains separately typed if enabled | causal provenance lost |
| Embeddings | Intake | same vector space for dedup | identity drift |
| Embeddings | Recurrence | cluster state built in active vector space | false recurrence |
| Embeddings | Relevance | question and seed vectors share representation | invalid surfacing scores |
| Recurrence | Gate | recurrence signal identity is not evidence identity | recurrence becomes fake evidence |
| Lifecycle | Gate | authority-bearing expiry follows one documented boundary | second authority writer |
| Gate policy | Current authorization | same named policy has same semantics | promoted-but-not-authorized paradox |
| Authority profile | Gate policy | default relation + override visible | Open/evidence-backed confusion |
| Gate | Orchestration | missing conditions translate into correct human handoff | user cannot tell who acts next |
| Contradiction state | Point-of-use | blocking always wins | contradicted seed influences answer |
| Gate | Relevance | only currently eligible seeds considered | stale authority used |
| Relevance | Point-of-use | selected seed still receives final allow/deny | relevance treated as permission |
| Point-of-use | Revision | only allowed seed context reaches reviser | policy bypass |
| Draft | Revision | original draft is real model input | full regeneration instead of revision |
| Revision | Observation ledger | revised output keeps SSL-exposed provenance | self-derived output appears independent |
| A-B control | Detection/history | control remains isolated | experiment contaminates system |
| Config | Persisted structural state | incompatible state rebuilds or starts new epoch | config says pairwise while clusterer restores |
| Config | Audit | prompt/model/embedding/recurrence/Gate all fingerprinted | runs cannot be interpreted later |
| Application orchestration | vNext UI | UI renders derived state, not own rules | backend/UI semantics drift |

# C. Implementation matrix

## C1. Foundation: authority and state invariants

**Priority**: P0  
**Proposed PR**: PR-A, 0.11 foundation

### Work

1. Replace current-Gate duplicate semantics with canonical policy-backed revalidation.
2. Remove legacy_evidence_required from normal strictness/preset paths; keep explicit compatibility access.
3. Decide and implement lifecycle expiry authority boundary so implementation matches ADR-009.
4. Prevent recurrence_mode / cluster_threshold hot changes from restoring incompatible cluster state.
5. Replace unsafe embedding force semantics with new-session/rebuild/re-embedding requirement.
6. Introduce the configuration-statefulness metadata needed by God mode.

### Main files

- src/shadowseed/gate/current_authority.py
- src/shadowseed/gate/policies.py
- src/shadowseed/gate/runtime_adapter.py
- src/shadowseed/lifecycle.py
- src/shadowseed/chat.py
- src/shadowseed/application/sessions.py
- src/shadowseed/application/models.py
- src/shadowseed/workbench/controller.py

### Tests

- same named Gate policy gives same current authorization result as canonical policy semantics;
- compatibility policy never appears in normal preset mapping;
- expiry cannot create an undocumented authority transition;
- cluster -> pairwise restore does not recreate clusterer;
- cluster threshold change cannot be overwritten by stale persisted state;
- embedding change after seeds fails closed unless explicit rebuild/new session path is selected.

### Dependency

Must land before prompt and UX changes that depend on stable semantics.

## C2. Orchestration application model

**Priority**: P0/P1  
**Proposed PR**: PR-B, human-SSL orchestration

### Work

Add an application-level orchestration result for session and seed.

Suggested fields:

~~~text
state: ssl_turn | optional_review | human_turn | blocked
reason_code
reason_text
required_action
optional_actions
no_action_effect
component
seed_id
~~~

Derive it from runtime state, not UI labels.

Rules include:

- below recurrence threshold under autonomous path -> ssl_turn;
- mature Assisted recurrence without trusted support -> human_turn;
- Controlled seed requiring support to progress -> human_turn when progression is being inspected/requested;
- autonomous/open unblocked seed -> ssl_turn or optional_review;
- open contradiction -> blocked;
- promoted but irrelevant -> ssl_turn/no action;
- current authorization failure after config change -> explicit explanation rather than generic “not allowed”.

### Main files

- src/shadowseed/application/inspection.py
- new application orchestration helper/module
- authority profile helpers
- contradiction inspection path

### Tests

- every authority regime maps to expected orchestration state;
- contradiction always maps to blocked;
- Assisted review IDs map to human_turn;
- session-level summary aggregates seed states deterministically;
- orchestration is read-only and does not change Gate or seed state.

## C3. Observation and self-derived signal split

**Priority**: P1  
**Proposed PR**: PR-C, observation provenance and experimental self-derived policy

### Work

1. Remove the conceptual equivalence between self-reinforcement and recurrence eligibility.
2. Keep every SSL-exposed CandidateObservation explicitly ssl_exposed with surfaced seed provenance.
3. Add SELF_DERIVED to the typed signal vocabulary if experiment S1 proceeds.
4. Provide fail-closed self_derived_signal_policy as baseline.
5. Add one bounded experimental policy behind Research/Advanced only.
6. Ensure SELF_DERIVED is never is_external_evidence and never RECURRENCE.
7. Add loop-depth / contribution audit fields needed by S1.

### Main files

- src/shadowseed/observations.py
- src/shadowseed/gate/signals.py
- src/shadowseed/gate/policies.py
- src/shadowseed/chat.py
- SessionConfig and inspection/audit projection

### Tests

- SSL-exposed observation can never serialize as clean independent recurrence;
- SELF_DERIVED cannot satisfy evidence-backed policy;
- fail-closed policy produces no authority contribution;
- bounded policy cannot create unbounded same-turn loop;
- causal surfaced_seed_ids remain available in audit;
- legacy observation schema remains readable.

### Decision status

Reopen/test, not yet a default. PR may implement experiment support without selecting permissive default.

## C8. Prompt experiments and default selection

**Priority**: P2  
**Proposed PR**: PR-H or research branch series

Run the Prompt Contract PvA only after C1-C7 provide stable plumbing.

Experiments:

- D1 answer-only vs current-pair detector;
- D2 English few-shots vs none/localized form-only examples;
- D3 forced first candidate vs explicit NONE;
- D4 downstream-only max words vs prompt-aligned max words;
- G1 current host prompt vs neutral host prompt;
- I1 current candidate framing vs candidate_context_v1.1;
- R1 free regeneration vs minimal_revision_v1;
- S1 fail-closed vs bounded SELF_DERIVED policy;
- A1 authority/orchestration regime selection for the 0.11 Research Preview default.

Default selection is evidence-driven. ADR-009 intentionally does not inherit the old evidence-backed default automatically.

# Definition of done for 0.11 alignment

The alignment phase is complete only when:

- every runtime setting has one owning component;
- current/pair/seed/cluster terminology is component-specific;
- every authority transition has one canonical boundary;
- the Workbench can state who is expected to act next and why;
- human-required actions are reachable from the UX;
- structural settings cannot silently reinterpret incompatible persisted state;
- same-turn revision receives the real draft;
- SSL-exposed observations keep causal identity;
- prompt provenance is exact and versioned;
- A/B remains non-mutating;
- each turn has a behavior/configuration fingerprint;
- all retained ADR invariants and new ADR-009 invariants are regression-tested.
